Modüler Monolith → Event Sourcing & CQRS

Order & Inventory bounded context’leri; fiziksel modül sınırları, aggregate tasarımı, event store (PostgreSQL 18.6), CQRS read model projeksiyonları. Giriş seviyesi DDD anlatımı yok — odak: tutarlılık sınırları, concurrency ve operasyonel gerçeklik.

🧭 Günün hedefleri

  • orders / inventory şemalarında modüler monolith iskeletini çalıştırmak (docker compose + solution yapısı).
  • Order aggregate için append-only event stream + optimistic concurrency (version).
  • MediatR ile command/query ayrımı; read model projeksiyonunun eventual consistency sınırlarını ölçmek.
  • gRPC pipeline’ı (FAZ 2) ile correlation / JWT claim taşıma konseptini Inventory tarafına bağlamak.

💥 Savaş hikayesi (War Story)

Senaryo: Avrupa’daki bir filo operasyon platformunda “Black Friday” gecesi PlaceOrder komutu 40k/dk’ya çıktı. Event store’a paralel yazım doğruydu; ancak read model projeksiyonu tek thread MediatR notification ile çalışıyordu. Dashboard stok “0” gösterirken aggregate hâlâ rezerve ediyordu — operasyon ekibi aynı SKU için manuel sipariş açtı ve oversell oluştu.

Kök neden: CQRS’te write path ile read path SLA’ları karıştırıldı; projeksiyon lag metriklenmedi; concurrency retry’ları OrderPlaced event’ini çift publish etti (idempotency key yoktu).

Çözüm: (1) Projeksiyonları channel tabanlı worker’a taşıdık, (2) CommandId ile idempotent handler, (3) Grafana’da projection_lag_seconds alert, (4) müşariyüzde “stale read” banner + version token. Gün 1 lab’ında katılımcılar aynı hatayı kasıtlı tekrarlar, sonra (1)+(2) ile düzeltir.

  3. Kriz senaryosu: çift event publish

    Order.Application içinde placeholder PlaceOrderCommandHandler yazılırken CommandId olmadan retry simüle edin:

    // Anti-pattern (lab A) — katılımcıya dağıt
public async Task Handle(PlaceOrderCommand cmd, CancellationToken ct)
{
    var order = OrderAggregate.Place(cmd.Sku, cmd.Qty);
    await _store.AppendAsync(order, ct);           // v1
    await _projector.ProjectAsync(order, ct);      // sync projeksiyon — bottleneck
    await _bus.PublishAsync(new OrderPlaced(...)); // retry'da duplicate
}

    Projeksiyon gecikmesini görmek için await Task.Delay(200) ekleyin; eşzamanlı 50 istek atın.

  4. Çözüm kodu: idempotency + async projeksiyon intent 
    public sealed record PlaceOrderCommand(Guid CommandId, string Sku, int Qty) : IRequest<Guid>;

public async Task<Guid> Handle(PlaceOrderCommand cmd, CancellationToken ct)
{
    if (await _idempotency.ExistsAsync(cmd.CommandId, ct))
        return await _idempotency.GetResultAsync(cmd.CommandId, ct);

    var stream = await _store.LoadAsync(cmd.Sku, ct);
    stream.PlaceOrder(cmd.Qty);
    await _store.SaveAsync(stream, expectedVersion: stream.Version, ct);

    await _idempotency.SaveAsync(cmd.CommandId, stream.Id, ct);
    await _outbox.EnqueueAsync(new OrderPlacedV1(stream.Id, cmd.Sku, cmd.Qty), ct);
    return stream.Id;
}

    Outbox tablosu Gün 2’de MassTransit ile tüketilecek; Gün 1’de yalnızca schema + enqueue yeterli.

⚠️ Gotcha (tuzak) uyarıları

.NET 10 JIT & field-backed properties (C# 14)

Aggregate’lerde field backed property kullanırken constructor + event rehydration aynı field’ı doldurmalı. Aksi halde JIT inline optimizasyonları debug/release farklı davranış gösterebilir — event sourcing testlerinizi Release configuration’da koşturun.

EF Core 10 split query

Read model’de çoklu collection include kullanıyorsanız AsSplitQuery() varsayılan stratejiniz olsun; tek query cartesian explosion ile PostgreSQL temp file açar — latency değil, disk I/O patlar.

Event store “upsert” anti-pattern

ON CONFLICT DO UPDATE event satırında kullanılmaz. Version PK ihlali concurrency sinyalidir — swallow etmeyin.

Modüler monolith → dağıtık transaction hayali

Order + Inventory aynı PostgreSQL instance’ında iki schema olsa bile, Gün 2’de servis ayrılınca 2PC geri gelmez. Gün 1’den itibaren saga / outbox dilini kullanın.

Span<T> (Gün 3 önizleme)

Gün 1’de string event payload’larında ReadOnlySpan<char> ile JSON parse denemeyin — UTF-16 string backing ile ref struct sınırları ihlal edilir. Telemetry lab’ında (Gün 3) byte[] / ReadOnlyMemory<byte> pipeline gösterilecek.
