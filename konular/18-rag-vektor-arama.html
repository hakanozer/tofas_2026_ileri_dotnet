RAG pipeline ve hata sınıfları

Ingestion, kaynak kimliği, content hash, version, tenant/ACL, chunk boundary, embedding model/version/dimension ve upsert semantics taşır. Chunk çok büyükse retrieval precision düşer; çok küçükse referans bağlam kaybolur ve embedding/token maliyeti artar. Chunking sabit karakter sayısına indirilmemeli; belge yapısı, başlık ve retrieval task'ı değerlendirilmelidir. Embedding model değişince vector space'ler doğrudan karşılaştırılamaz; model version/dimension ile ayrı index veya kontrollü re-embedding gerekir.

Query-time retrieval'da semantic similarity keyword/identifier aramasını kaçırabilir; hybrid search lexical/vector sonuçlarını birleştirir. HNSW/IVF index recall, latency, memory ve build cost tradeoff'udur; distance metric, normalization ve embedding modelin önerdiği metric doğru olmalıdır. Top-k, threshold, metadata filters ve reranking evaluation ile belirlenir. Score karşılaştırılabilir relevance probability değildir. LLM context window ve prompt injection riskini yönetmek için retrieved text'i trusted system instruction'dan ayrı, untrusted data olarak işaretleyin.

Bu repodaki pgvector implementasyonu

PgVectorDocumentStore, vector(1536) embedding kolonu, HNSW cosine index ve PostgreSQL full-text GIN index kuruyor; ingestion source + chunk index ile upsert yapıyor. DocumentChunker, EmbeddingCache ve RagRetriever pipeline'ın diğer parçalarını gösteriyor. Compose'da pgvector destekli PostgreSQL image'i gereklidir; stock PostgreSQL image'ında extension hazır bulunacağı varsayılmamalıdır.

Retrieval SQL'i vector ve keyword top 20 setlerini full outer join ile harmanlıyor, sabit 0.7/0.3 ağırlık ve vector minScore kullanıyor. Bu skor/threshold dataset için kalibre edilmiş olduğu anlamına gelmez. Query `topK` sınırı, tenant/ACL metadata filtering, document freshness ve index scale test edilmelidir. Deterministic source ID aynı source update için chunk count küçüldüğünde eski fazladan chunk'ların silinip silinmediği ayrıca kontrol edilmelidir.

Hata yönetimi: “boş retrieval” ile “retrieval hatası” aynı değildir

RagRetriever, embedding/cache/store hatasını loglayıp boş liste dönüyor; Program.cs sonrasında prompt'a retrieved context eklemeden devam edebiliyor. Üst katmanın “Bu bilgi elimde yok” demesi tasarım hedefi olsa da retrieval unavailable ile corpus'ta sonuç yok durumunu ayırmamak kullanıcıya güvenilir olmayan bağlamsız cevap döndürme riski taşır. Production API, policy'ye göre açık degraded status, fallback answer, retryable error veya no-answer formatını ayırmalıdır. Source citation yoksa answer'da source yokluğunu açıkça belirtin.

Ingestion'da dedupe, update/delete, poison document quarantine, embedding provider retry/rate limit ve batch checkpoint tanımlayın. Sorguda timeout, token budget, top-k/corpus size ve source authorization sınırlandırın. KVKK/GDPR deletion için yalnızca primary row değil vector index, embedding cache, replicas, backups, logs ve provider retention da planlanmalıdır.

Kaliteyi ölçün

Golden query set'inde retrieval recall@k/MRR/nDCG, document permission leak, freshness, citation correctness ve answer faithfulness ölçün. “LLM yanıtı kulağa iyi geliyor” kabul kriteri değildir. Human review, rubric ve model-as-judge yardımcıdır ama judge model hatalı/biased olabilir; kritik workflow'da deterministic assertions ve domain owner review ile destekleyin. Regression test'leri chunker, embedding version, SQL weight, reranker ve prompt değişikliklerini ayrı ayrı izole etmelidir.

Embedding ömrüEmbedding bir PII-free anonim veri değildir: orijinal içeriğin anlamını ve potansiyel hassas bilgiyi taşıyabilir. Access control, retention, encryption, tenant partition ve erase workflow embedding'leri de kapsamalıdır.

Kod yürüyüşü: ingest'ten grounded cevaba

RAG (retrieval-augmented generation: model yanıtından önce kaynak bağlamı getirme) iki ayrı kalite problemini birleştirir: ingestion doğru chunk/embed/index yapmalı, query tarafı alakalı ve yetkili bağlamı bulmalı. Repoda Markdown başlık/paragraf yapısını koruyan chunker, embedding cache, pgvector document store ve hybrid retrieval bileşenleri bulunuyor.

// AiMcpServer/Program.cs ingestion akışının özeti
var chunks = DocumentChunker.Chunk(request.Content).ToList();
var embeddings = sp.GetRequiredService<Kernel>().Services
    .GetRequiredService<ITextEmbeddingGenerationService>();
var payload = new List<(int index, string content, float[] embedding)>(chunks.Count);
for (var i = 0; i < chunks.Count; i++)
{
    var embedding = await embeddings.GenerateEmbeddingAsync(chunks[i], cancellationToken: ct);
    payload.Add((i, chunks[i], embedding.Vector.ToArray()));
}
var store = sp.GetRequiredService<PgVectorDocumentStore>();
await store.UpsertChunksAsync(request.Source, payload, ct);

Query'de soru embedding'i üretilir, vector + lexical search birleştirilir, top-k/min score ile adaylar süzülür; sonra kaynak sınırı açık prompt'a girer. Chunk size/overlap, tokenizer/model dimensions, embedding model version, metadata ACL, freshness, dedupe/upsert key, top-k/score threshold ve reindex planı retrieval kalitesini belirler. Embedding dimension değişirse mevcut index/schema uyumsuz hale gelebilir.

[Chunking.cs](../src/Services/AI/AiMcpServer/Rag/Chunking.cs), [RagRetriever](../src/Services/AI/AiMcpServer/Rag/RagRetriever.cs), [PgVectorDocumentStore](../src/Services/AI/AiMcpServer/Rag/PgVectorDocumentStore.cs) izlenmeli. Şu an retrieval hata verirse boş listeye degrade olma davranışı var; kullanıcıya “kanıt bulunamadı” ile “retrieval altyapısı arızalı” aynı yanıt olarak gizlenmemelidir. Tenant/permission filter'ı retrieval sorgusunun içinde olmalı; prompt'a sonradan eklemek veri sızıntısını engellemez.

Evaluation loopGolden query set'te recall@k, precision/MRR, citation correctness, freshness, unauthorized retrieval, no-answer calibration, latency ve embedding cost ölçün. “Model düzgün yanıt verdi” RAG retrieval'ın doğru olduğuna kanıt değildir.

Tartışma

Tek bir operasyon prosedürü belgesini iki chunk stratejisiyle ingest edip top-k sonuçlarını karşılaştırın. Sonra soru içindeki ürün kodunu lexical aramanın, doğal dil niyetini embedding'in neden daha iyi bulduğunu gösterin; hibrid skor ağırlığını örnek test setiyle değiştirin.

  • İki tenant aynı belge metnine erişim yetkisi farklıysa retrieval filter hangi aşamada zorunlu olmalı?
  • Vector score yüksek ama sonuç eski ve iptal edilmiş dokümana ait: retrieval ranking mi freshness policy mi?
  • Embedding provider erişilemez ama keyword index çalışıyorsa ürün hangi degraded davranışı kabul eder?
