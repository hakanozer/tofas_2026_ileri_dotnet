MCP entegrasyon protokolü ne sağlar?

Model Context Protocol, AI host/client ile context/tools sağlayan server arasında standart etkileşim modelidir. Tool discovery ve invocation, resources ve prompts gibi capability'leri tanımlar; transport ve protocol version tarafındaki detaylar specification ve SDK sürümüne bağlıdır. MCP model/provider seçimi, tenant entitlement, OAuth policy, business authorization, data isolation veya result validation'ı otomatik sağlamaz. Remote server'ı “modelin verdiği isimle güvenli çağrılabilir function” gibi varsaymayın.

MCP server, exposed tool list'ini en az yetkiyle sınırlandırmalı; input schema ve output size/format validate etmeli; çağıran principal/tenant'i server'a doğrulanmış channel ile taşımalı; authorization'ı tool'un domain operation'ında tekrar uygulamalı. Tool tarafında audit kim, hangi tool, hangi resource, hangi sonuç ve hangi policy kararı bilgisini veri minimizasyonuyla kaydeder. Tool description prompt-injection'e karşı güvenlik filtresi değildir.

Projede MCP server ve tool guardrails

AiMcpServer, ModelContextProtocol.AspNetCore 2.2.0 ile HTTP transport ve assembly'den tool registration yapıyor; MapMcp() endpoint'ini ekliyor. Tool implementasyonları Tools/ içindeki typed inventory/order sözleşmelerini kullanıyor; query service'leri mevcut durumda in-memory demo'dur.

ToolAuthorizationFilter, `AsyncLocal` user context, role allowlist, deny-by-default, audit ve 8000 karakter output bound içeriyor. Bu yalnızca uygulama içi authorization filtresidir; uygulama request başlığından X-User-Id, X-Tenant-Id, X-User-Roles okur. Bu header'lar yalnızca güvenilir gateway tarafından set edilip dışarıdan gelen değerler siliniyor/overwrite ediliyorsa güvenilirdir; doğrudan service erişimi, header spoofing ve confused-deputy testi gerekir. Filter, audit kaydı başarısızlığı ve tool side-effect idempotency'sini de ayrıca ele almalıdır.

MCP protocol versionSDK package sürümü ile MCP specification sürümü aynı sayı değildir. Eğitimde protocol negotiation, transport, authorization ve security özelliklerini `ModelContextProtocol.AspNetCore` release notes ve güncel MCP specification üzerinden doğrulayın; eski/hazır varsayımları “MCP standardı hep böyle” diye sunmayın.

Multi-agent ne zaman gerçekten gerekli?

Birden çok agent rolü (planner/researcher/reviewer/executor) bağımsız araç ve context gerektiren, paralellik kazandıran ve sonuç kalitesi ölçülebilen görevlerde yararlı olabilir. Basit workflow, deterministic state machine, tek agent+tool veya normal service orchestration daha ucuz ve denetlenebilir olabilir. Bir agent'in başka agent üretmesi recursive plan, loop, prompt/token artışı, latency ve hata olasılığını yükseltir. Her delegate için max depth, task budget, timeout, cancellation, tool allowlist, output schema ve audit tanımlanmalıdır.

Coordinator agent karar verirken safety boundary değildir; her tool call API katmanında yetkilendirilir. Agent-to-agent çıktı untrusted input gibi ele alınır. Planner'ın “sipariş iptal et” talimatı domain policy olmadan doğrudan command çalıştıramaz. Multi-agent kalite artışını aynı benchmark task setinde task success, policy violation, p95 latency, token cost ve human handoff oranıyla ölçün.

Üretim için operasyon ve güvenlik kontrolleri

  • Remote MCP transport için TLS, caller auth, audience/scope ve per-tool authorization.
  • Tool input/output schema, payload cap, timeout, cancellation ve rate limit.
  • Tool side effect'leri için idempotency key, preview/confirm ve high-risk action human approval.
  • Resource URI access kontrolü; kullanıcıya ait olmayan source'a LLM üzerinden erişimi önleme.
  • Protocol/client/server version compatibility, tool discovery cache ve deprecation süreci.
  • Trace context, tool latency/error/cost metric; request/prompt'ta hassas içerik loglamama.

Kod yürüyüşü: MCP tool discovery, auth ve function invocation

MCP (Model Context Protocol: model istemcisi ile tool/resource sunucusu arasındaki protokol) agent'ın dış dünyaya erişmesini sağlar; tool çağrısı güvenli diye varsayılmaz. Repo AI server'ında MCP HTTP transport kuruluyor ve tools assembly'den yükleniyor. Request başında UserContext middleware'i tenant/role context'i AsyncLocal'a koyar; authorization filter çağrı anında allowlist kontrolü yapar.

// AiMcpServer/Program.cs — mevcut MCP host wiring
builder.Services.AddMcpServer()
    .WithHttpTransport()
    .WithToolsFromAssembly();

app.MapMcp(); // user/tenant context middleware'inden sonra map edilir

Bu sıra önemlidir: filter execution zamanı context yoksa “anonymous/default” policy'ye düşebilir. RoleBasedToolAllowList mevcut roller/tool adlarıyla karar verir; filter denied çağrıyı audit eder ve result'ı sınırlı boyuta kırpar. Tool schema description da prompt injection/social engineering yüzeyidir; input validate, tenant scope server-side derive, timeout/cancellation uygula ve side-effectful command için approval/idempotency ekle.

[MCP host](../src/Services/AI/AiMcpServer/Program.cs), [authorization/audit filter](../src/Services/AI/AiMcpServer/Guardrails/Guardrails.cs), [InventoryTools](../src/Services/AI/AiMcpServer/Tools/InventoryTools.cs) ve [OrderTools](../src/Services/AI/AiMcpServer/Tools/OrderTools.cs) dosyalarını birlikte açın. Önemli uygulama sınırı: Order/Inventory tool query'leri gerçek servis API'si değil, deterministik in-memory demo verisi kullanır.

MCP ≠ authorizationProtocol tool'ları ilan edip çağırmayı standardize eder; kim çağırabilir, tenant hangi kaynağı görebilir, tool side effect nasıl denetlenir uygulama sorumluluğudur. Multi-agent mimarisi ancak ayrı uzmanlık/izolasyon ölçülebilir fayda sağlıyorsa; aksi halde maliyet, latency ve orchestration failure ekler.

Tartışma

MCP tool discovery'den invocation'a kadar akışı çizdirin; tool schema'ya “tenantId” alanı eklemek caller authorization yerine geçmez. Sonra gateway'in doğrulanmış principal'ı server'a nasıl aktaracağını ve backend'in hangi iddiaları tekrar doğrulayacağını tartıştırın.

  • Model `get_order_status` çağrısını öneriyor ama kullanıcı support role değil: red kararı modelde mi server'da mı uygulanır?
  • İki agent aynı idempotency key ile aynı işlemi yapıyor; downstream command'in davranışı nedir?
  • MCP service yeni tool yayınladı; production caller'lar mevcut allowlist dışında bu tool'u görebilir mi?
