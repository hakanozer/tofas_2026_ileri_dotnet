Microsoft.Extensions.AI ve Semantic Kernel aynı katman değildir

Microsoft.Extensions.AI ortak .NET abstraction ve middleware yaklaşımı sunar: IChatClient, IEmbeddingGenerator<TInput,TEmbedding>, tool invocation, telemetry ve caching extension'ları. Uygulama/provider adapter'larını değiştirmeyi ve .NET DI/observability ile entegre etmeyi kolaylaştırır; model kabiliyetlerini her provider'da eşit hale getirmez. Model-specific structured output, content block, tool-call ve streaming davranışlarını yine test etmek gerekir.

Semantic Kernel plugin/function catalog, prompt ve orchestration seviyesinde daha yüksek seviye bir framework'tür; provider adapter ve chat-client abstraction'ının yerine geçmez. Proje Microsoft.SemanticKernel 1.81.0 ve OpenAI connector kullanıyor. `RagRetriever` içindeki ITextEmbeddingGenerationService obsolete olarak yorumlanmış; yeni abstraction'a geçiş, package sürümü/API compat, vector model dimension ve integration test ile yapılmalıdır. Bu doküman geçişi otomatik olarak repo'ya uygulamaz.

Model/provider erişimini typed application port arkasında tutun. Prompt assembly, tool authorization ve output validation business orchestration'dan açıkça ayrılmalıdır. Provider credential'ı secret manager'dan alın; source, image, logs ve client request'ten sızdırmayın.

Projede AI request lifecycle

AiMcpServer Program.cs, config varsa OpenAI veya OpenAI-compatible endpoint için Semantic Kernel ChatCompletion/Embedding servislerini ekliyor. Model key yoksa host ayağa kalkabiliyor; `/ask` endpoint'i 503 dönüyor. Bu, dependency yokken yanıltıcı başarılı metin üretmemek açısından doğru bir explicit failure yaklaşımıdır. Inventory/Order plugin'leri şu an in-memory deterministic demo data kullanır, gerçek servis client'ı değildir.

YARP gateway AI route için PII masking, tenant token budget ve proxy routing yapıyor. PII masking regex-based ve middleware request gövdesini RAM'e alarak işler; body size limit/streaming ve binary/large input için uygun değildir. Token-count stream'in chars/4 tahmini provider'ın gerçek usage alanı değildir. Tenant quota read sonra kullanım yazımı atomik rezervasyon değildir; fail-open Redis hatasında maliyet limiti aşılabilir. Bir gateway'in varlığı model erişiminin policy-enforced olduğunu kanıtlamaz: AI backend gateway'i doğrudan public edilememeli ve header identity kaynağı doğrulanmalıdır.

LLM gateway sorumlulukları ve failure mode

  • Policy: tenant entitlement, allowed model/provider/region, data classification, rate/token budget ve timeout.
  • Reliability: concurrency limit, queue budget, circuit breaker, retry yalnızca güvenli/idempotent durumlar, cancel propagation, provider failover.
  • Cost: input/output token usage, model tier, embedding cache, per-tenant ledger ve alert.
  • Privacy: prompt/response log redaction, retention, residency, provider training/data-use terms.
  • Safety: output schema validation, tool allowlist, authorization tekrar kontrolü ve prompt injection boundary.

Model routing'i yalnızca prompt uzunluğuna göre seçmek kalite/maliyet/PII politikasını karşılamaz; benchmark/evaluation dataset ile task-specific routing ölçülmelidir. Fallback model farklı capability/language/structured output sunabilir. Fallback için confidence threshold ve explicit degraded response tasarlayın; model hallucination'ını HTTP 200 başarı gibi raporlamayın.

Kod yürüyüşü: request lifecycle ve model gateway kararları

AI endpoint yalnızca prompt'u modele forward etmez: tenant/user context, RAG retrieval, system/user prompt construction, tool authorization, provider çağrısı, usage ölçümü ve error mapping tek lifecycle'da birleşir. Repoda Semantic Kernel kernel singleton olarak kuruluyor; model key yoksa host başlar ama ask endpoint'i provider kullanımında 503 döndürür. Microsoft.Extensions.AI abstraction'ı ile Semantic Kernel orchestration'ını aynı katman gibi sunmayın.

// AiMcpServer/Program.cs — gerçek /ask akışının özeti
var hits = await retriever.RetrieveAsync(request.Prompt, ct);
var (systemPrompt, userPrompt) = BuildPrompts(request.Prompt, hits);
var history = new ChatHistory(systemPrompt);
history.AddUserMessage(userPrompt);
var result = await chat.GetChatMessageContentsAsync(
    history, settings, kernelInstance, ct);
var answer = result.LastOrDefault()?.Content ?? "Bu bilgi elimde yok";
RecordTokens(result, chatModel);

YARP AI route'u rate limit/token budget ve PII masking middleware'lerinden geçer; route permission, model routing ve retry policy'nin gerçek enforcement'ı source'da kontrol edilmeli. Request ID, tenant context, prompt version, model/provider/deployment, latency, token usage ve outcome loglanabilir; prompt body, secret ve PII telemetry'ye yazılmamalı. Retry yalnız idempotent/provider-supported güvenli işlemlerde ve request budget içinde.

Tartışma

Aynı business use-case'i doğrudan model SDK'sına bağlı kod, Microsoft.Extensions.AI interface'i ve Semantic Kernel plugin'iyle ayrı ayrı çizin. Her abstraction'ın hangi değişimi gizlediğini, hangisini gizleyemediğini sorun. Repo'daki demo services ile gerçek gRPC integration planını ayırt edin.

  • Redis quota store unreachable ise cost-control fail-open mi fail-closed mi olmalı? İş sürekliliği ve maliyet riskini kim kabul eder?
  • Model server function call için inventory sorgusu önerdi; kullanıcı o tenant'ta inventory okumaya yetkili mi kim doğrular?
  • Model provider değişince structured output, safety policy ve latency SLO hangi contract testleriyle korunur?
