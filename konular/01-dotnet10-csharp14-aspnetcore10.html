.NET 10, C# 14 ve ASP.NET Core 10

Platform sürümünü hedef framework, SDK, runtime ve dil sürümünden ayırarak ele alın. Katılımcı, üretimde hangi bileşenin güncellendiğini ve neden yalnızca derlemenin yeterli kanıt olmadığını kavrasın.

Hedef: .NET uzmanlarıÖrnek repo: net10.0 / C# 14

Dersin hedefi ve akışı

Önce platform parçalarını ayırt edin; sonra C# 14 yeniliklerinin kod okunabilirliğine etkisini ve ASP.NET Core uygulamasının host/pipeline yaşam döngüsünü tartışın. Son bölümde bu depodaki sürüm seçimini okuyup bir sürüm yükseltmesinin gerçek kapsamını çıkarın.

Platform katmanlarını birbirine karıştırmayın

net10.0, TFM (Target Framework Moniker: hedef framework'ü ve kullanılabilir API yüzeyini tanımlayan kısa ad) değeridir; derleme sırasında hangi framework API'lerinin kullanılacağını belirtir. .NET SDK (Software Development Kit: derleyici, MSBuild ve CLI araçları) restore/build/publish yapar; .NET Runtime (çalışma zamanı: uygulamanın IL kodunu çalıştıran JIT, GC ve temel kütüphaneler) uygulamayı çalıştırır. ASP.NET Core Shared Framework (ASP.NET Core çalışma zamanı bileşenleri) web uygulamasının hosting, middleware ve HTTP altyapısını sunar.

Framework-dependent deployment (hedef makinede .NET Runtime kurulu olmasını gerektiren dağıtım) genellikle küçük uygulama çıktısı üretir; container/host imajında uygun runtime bulunmalı ve runtime patch'i host sahibi tarafından güncel tutulmalıdır. Self-contained deployment (uygulama ile seçilen .NET Runtime'ı birlikte yayımlayan dağıtım) host'a önceden runtime kurulumu gerektirmez; fakat her işletim sistemi/CPU için doğru RID (Runtime Identifier: ör. linux-arm64 gibi yayın hedefi) seçilmeli, runtime güvenlik güncellemesi uygulama yeniden publish edilerek alınmalıdır. İkisi de tek başına Native AOT değildir; AOT ayrı bir yayın tercihi ve uyumluluk testidir.

Depodaki Directory.Build.props, tüm projelerde net10.0, nullable referans tipleri ve LangVersion=14 belirliyor. Makinede kurulu SDK 10.0.401 ve runtime 10.0.12 ile solution build edildi. Kök README'de beklenen SDK 10.0.402 yazması gerçek kurulumla aynı şey değildir; `global.json` olmadığı için SDK seçimi makine politikasına bağlıdır. CI'da SDK bandını sabitleyin, runtime patch'lerini ise destek politikasına göre düzenli güncelleyin.

Sürüm desteği ≠ otomatik güncelleme. Microsoft'un .NET sürüm politikası .NET 10'u LTS olarak listeler ve destek bitişini Kasım 2028 olarak verir. Destek dönemi, uygulamanın bağımlılıkları, container tabanı ve güvenlik yamalarının güncel olduğu anlamına gelmez.

C# 14: hangi yenilikler nerede değer üretir?

C# 14 (.NET 10 ile yayımlanan C# dil sürümü) derleyici özelliklerini getirir; .NET Runtime sürümüyle aynı kavram değildir. Projedeki Directory.Build.props, bütün projelerde LangVersion=14 seçiyor. Aşağıdaki her örneğin yanında hangi günlük problemi çözdüğü ve hangi koşulda tercih edileceği anlatılır. Bunlar küçük, bağımsız dil örnekleridir; repository'nin iş kuralı olarak kullanılmaları gerektiği anlamına gelmez.

1. Extension Members (Genişletme Üyeleri): metot yanında property ve static üyeler

Eski extension method yalnızca statik extension metodu instance metodu gibi çağırırdı; alan/property ekleyemezdi. C# 14 extension block'ları instance üyelerini ve type üzerinde static üyeleri gruplayabilir. Gateway'de tekrar eden tenant claim okuması için örnek:

public static class GatewayContextExtensions
{
    extension(HttpContext context)
    {
        public string? TenantId =>
            context.User.FindFirst("tenant_id")?.Value;

        public bool HasTenant =>
            !string.IsNullOrWhiteSpace(context.TenantId);
    }
}

// Kullanım: controller/middleware içinde:
var tenantId = httpContext.TenantId;

Bu API extension property'yi gerçek HttpContext sınıfına eklemez; receiver (genişletilen alıcı tür) üzerinde çağrılan derleme zamanı üyeleri sunar. Domain policy'yi global extensions sınıfına yığmayın: extension'lar iş kuralını gizleyebilir veya aynı isimdeki üyelerle belirsiz overload oluşturabilir.

2. Null-Conditional Assignment (Null Koşullu Atama): guard tekrarını azaltır

Önceden null kontrolüyle sarılan property/element assignment ve bileşik atama (+=/-=) artık ?. / ?[] ile sol tarafta yapılabilir. Alıcı null ise sağ taraf da değerlendirilmez; yan etkili hesap gereksiz yere çalışmaz.

// Önce:
if (sagaState is not null)
    sagaState.FailureReason = "Inventory timeout";

// C# 14:
sagaState?.FailureReason = "Inventory timeout";
sagaState?.FailureReason = BuildDiagnosticMessage();
sagaState?.RetryCount += 1;

Bu yalnızca nesne null iken atamayı atlar; null değerin iş kuralında geçerli olup olmadığını çözmez. Kritik transition'da if (sagaState is null) throw ... daha açık olabilir. ++/-- null-conditional assignment ile kullanılmaz.

3. nameof ile Sınırsız Generic Tür Desteği: tür argümanlarını seçmeden isim alır

Unbound generic type (tür argümanları verilmemiş generic tanım) için nameof artık List<> veya Dictionary<,> kabul eder:

var collectionName = nameof(List<>);  // "List"
var mapName = nameof(Dictionary<,>); // "Dictionary"
var propertyName = nameof(TenantOptions.TenantId);

Bu, diagnostics/validation metninde generic tipin specialization'ı bilinmediğinde reflection'sız sembol adı verir. nameof(List<int>) önceki sürümlerde de mümkündü. nameof assembly-qualified metadata adı sağlamaz.

4. Span<T> / ReadOnlySpan<T> için Örtük Dönüşümler: gereksiz geçici kopyaları azaltır

C# 14, T[], Span<T> ve ReadOnlySpan<T> arasındaki bazı örtük dönüşümleri dilin daha fazla bağlamında tanır; extension receiver ve generic type inference (generic tür çıkarımı) gibi durumlarda doğrudan kullanım kolaylaşır. Örneğin array artık ReadOnlySpan<int> receiver'lı extension method'a doğrudan bağlanabilir:

public static class TelemetrySpanExtensions
{
    public static long SumValues(this ReadOnlySpan<int> values)
    {
        long sum = 0;
        foreach (int value in values)
            sum += value;
        return sum;
    }
}

int[] sample = [12, 18, 42];
long total = sample.SumValues(); // array -> ReadOnlySpan receiver conversion

Repodaki Kafka consumer ise buffer sahipliğini ve gerçek payload uzunluğunu açıkça yönettiği için AsSpan(0, length) çağırır:

byte[] rented = ArrayPool<byte>.Shared.Rent(kafkaValue.Length);
kafkaValue.AsSpan().CopyTo(rented.AsSpan());

// Yalnızca payload uzunluğu görünür; pool kapasitesi payload değildir.
TelemetryPayload payload =
    TelemetryPayload.DeserializeFromUtf8(
        rented.AsSpan(0, kafkaValue.Length));

Span<T> değiştirilebilir, ReadOnlySpan<T> salt-okunur bellek penceresidir; kendileri veri kopyası değildir. Span ref-struct yaşam kuralları nedeniyle heap'e/normal async state machine'e gelişigüzel taşınamaz. Dönüşümler buffer ownership, slice length ve ArrayPool.Return sorumluluğunu kaldırmaz; repodaki buffer işlem tamamlanınca elle iade edilir.

5. Lambda Parametrelerinde Değiştiriciler: modifier yaz, parametre türünü hedef delegate'den al

Hedef delegate tipi biliniyorsa lambda parametre tipini tekrar yazmadan ref, in, out, scoped ve ref readonly modifier kullanılabilir. Bu, özellikle generic delegate ve büyük struct/span API'lerinde signature tekrarını azaltır.

delegate bool TryParseValue<T>(string text, out T result);
TryParseValue<int> parseInt =
    (text, out value) => int.TryParse(text, out value);

var succeeded = parseInt("42", out var quantity);

out çağrı öncesi değer istemeyen ve çağrı içinde değer üreten parametredir. in/ref readonly mutasyonsuz by-reference; ref okuma-yazma by-reference; scoped referansın escape/lifetime kapsamını sınırlar. Lambda modifier'ı hedef delegate signature ile eşleşmelidir; params için tür yine açıkça yazılır.

6. field Anahtar Sözcüğüyle Desteklenen Özellik: backing-field kodunu azaltır

Backing field (property değerini saklayan özel alan) daha önce ayrıca tanımlanırdı. field, derleyicinin oluşturduğu alana accessor içinde erişir; örneğin tenant ayarını trim edip boş değeri reddeder:

public string TenantId
{
    get;
    set => field = string.IsNullOrWhiteSpace(value)
        ? throw new ArgumentException(
            "TenantId is required.", nameof(value))
        : value.Trim();
} = "default";

Bu yalnızca accessor yazımını kısaltır; options validation ve domain invariant'ını otomatik çözmez. Aynı tipte field isimli sembol varsa @field veya this.field ile ayrıştırın. Üretimde invalid config'i startup'ta görünür kılın; sessizce default tenant'a düşmeyin.

7. Partial Events (Kısmi olaylar): generated contract ile accessor implementasyonunu ayırır

Partial type (aynı sınıfın birden çok kaynak dosyasına bölünmesi) kullanıldığında source generator (kaynak kod üreteci) event deklarasyonunu oluşturabilir; elle yazılan dosya event'in subscriber listesini yöneten add/remove accessor'larını sağlar. Tanımlayan ve implement eden deklarasyon aynı signature'a sahip olmalı; event implementasyonu iki accessor'ı da içermelidir.

// InventoryClient.Contracts.g.cs — generator'ın ürettiği deklarasyon
public partial class InventoryClient
{
    public partial event EventHandler? Connected;
}

// InventoryClient.Events.cs — elle yazılan accessor implementasyonu
public partial class InventoryClient
{
    private EventHandler? _connected;

    public partial event EventHandler? Connected
    {
        add => _connected += value;
        remove => _connected -= value;
    }
}

Örneğin generated proxy event imzası sabit kalırken transport'a özgü abonelik yönetimini ayrı dosyada tutabilirsiniz. Generator veya implementasyon eksikse partial member tamamlanmayacağı için build hata vermelidir; event'in kendisi thread-safe dispatch garantisi sağlamaz.

8. Partial Constructors (Kısmi oluşturucular): üretilen koda ait kurulum noktasını tamamlar

Source generator bir constructor'ın imzasını ve elle yazılan partial type ikinci deklarasyonda gövdeyi sağlayabilir. Böylece üretilen API şekli ile kullanıcı doğrulaması ayrılır; ikisinin de aynı parametre listesini/erişilebilirliği taşıması gerekir.

// InventoryClient.Contracts.g.cs — constructor deklarasyonu
public partial class InventoryClient
{
    public partial InventoryClient(string endpoint);
}

// InventoryClient.cs — constructor implementasyonu
public partial class InventoryClient
{
    private readonly string _endpoint;
    public partial InventoryClient(string endpoint)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(endpoint);
        _endpoint = endpoint;
    }
}

base(...)/this(...) initializer'ı yalnızca implementing declaration'da olabilir. Bu özellik generated client veya platform parçasını ayırabilir; normal business class'ı keyfi dosyalara bölmek takip maliyetini artırır.

9. User-Defined Compound Assignment Operators (Kullanıcı tanımlı bileşik atama işleçleri)

Daha önce budget -= used, operator - ile yeni değer üretip sol değişkene atardı. C# 14 türün bileşik atamayı yerinde düzenlemesine izin verir; büyük mutable türlerde ara nesne/kopya maliyetini azaltabilir.

public sealed class TokenBudget
{
    public int Remaining { get; private set; }

    public void operator -=(int used)
    {
        if (used < 0 || used > Remaining)
            throw new InvalidOperationException("Budget exceeded.");
        Remaining -= used;
    }
}

budget -= providerReportedUsage;

Operatörün yan etkisi şaşırtıcı olabilir; aliasing (aynı nesneye birden fazla referans), value type kopyası ve thread-safety ayrıca düşünülmelidir. Bu örnek in-memory mutasyondur; Redis üzerinde atomik kota düşümü değildir ve distributed lock yerine geçmez.

10. File-Based Apps için Yeni Ön İşlemci Yönergeleri: proje dosyasız küçük araç

#: satırları C# compiler macro'su değildir. .NET 10 SDK build sistemi, dosya tabanlı uygulamada #:package, #:project, #:property ve #:sdk yönergelerini yorumlar; güncel SDK dokümanında #:include için 10.0.300 ve sonrası koşulu belirtilir. Tek dosya uygulama dotnet run --file diagnostic.cs ile çalıştırılabilir.

#:property TargetFramework=net10.0
Console.WriteLine("service=inventory; healthy=true");

Çalıştırma: dotnet run --file diagnostic.cs; beklenen çıktı service=inventory; healthy=true. Bu, yerel log/health verisi inceleyen kısa araç için hızlı başlangıçtır; repository'deki çok projeli solution, CI, merkezi paket yönetimi, container publish veya uzun ömürlü service'e alternatif değildir. File-based app'in trim/AOT yayın varsayımlarını dikkate alın; reflection tabanlı JSON serialization gibi API'ler çalışmayabilir veya source generation isteyebilir. #:package kullanırken sürüm sabitleyin; bu biçim de supply-chain ve secret kurallarına tabidir.

Kritik özetC# 14'ün on başlığı da yukarıda ayrı ayrı işlendi. Dil yenilikleri runtime upgrade değildir. C# compiler SDK'nin parçasıdır; eski SDK aynı kaynak kodu derleyemeyebilir. Çözümü CI SDK bandı ve proje hedefleriyle doğrulayın.

Bu sözdizimini “daha yeni, dolayısıyla daha iyi” diye yaygınlaştırmayın. Public API'lerde analyzer/IDE, SDK ve ekip dil seviyesiyle uyumu; framework library'sinde ise tüketicinin compiler desteğini değerlendirin. Örneğin eski target'lara multi-target eden bir library, .NET 10'a özgü API'leri koşullu derleme olmadan kullanamaz.

ASP.NET Core: host ve istek hattı

Depodaki gateway WebApplication.CreateBuilder ile configuration (ayar kaynakları), logging (log sistemi) ve DI (dependency injection: bağımlılıkları çalışma anında bağlama) kurar; authentication/authorization, correlation/claim, PII maskeleme, token budget ve YARP proxy middleware sırası güvenlik ve semantiği etkiler. Middleware (HTTP isteği üzerinde sırayla çalışan bileşen) aşağı akışta request'i, dönüşte response'u işler; endpoint mapping ise uygulamanın route yüzeyini belirler. PII middleware'i proxy'den sonra çalışırsa üçüncü tarafa ham içerik gidebilir. Authentication sonrası tenant claim'i güvenilir hale gelir; istemcinin serbestçe verdiği header'ı doğrudan kimlik kabul etmek güven sınırını deler.

// ApiGateway/Program.cs — repository'deki gerçek sıralamanın özeti
app.UseAuthentication();
app.UseAuthorization();
app.UseCorrelationAndClaimInjection();
app.UsePiiMasking();
app.UseLlmTokenBudget();

app.MapReverseProxy(proxyPipeline =>
{
    proxyPipeline.UseMiddleware<GatewayRateLimitingMiddleware>();
});

YARP (Yet Another Reverse Proxy: ASP.NET Core üzerinde ters proxy kütüphanesi) route'u yarp.json'dan okur; /api/orders yolunu Order cluster'ına, /api/inventory'yi Inventory cluster'ına yönlendirir. Rate limit middleware'inin proxy pipeline'ında olması route metadata'ya erişmek içindir. Gerçek deployment'ta downstream servis doğrudan dışarı açılmamalı; gateway'in eklediği tenant/user header'ları yalnızca gateway'den kabul edilmeli veya doğrulanmış identity taşımalıdır.

ASP.NET Core 10'un release-notes sayfasındaki özellikleri kullanmadan önce ihtiyaç, runtime ve paket uyumunu doğrulayın. Mevcut solution build'inin başarılı olması endpoint'lerin, kimlik sağlayıcısının, mesaj broker'ının veya ölçek altında davranışın doğrulandığını göstermez.

Tartışma

Tahtaya “SDK ≠ runtime ≠ target framework ≠ language version” yazıp katılımcılara container imajı, CI agent ve developer workstation'da her birinin nerede bulunduğunu sordurun. Ardından root README ile Directory.Build.props'u yan yana açın: yazılı hedef ile gerçek build kanıtını ayırın.

  • Servicing güncellemesini hangi sinyal, hangi ekip ve hangi rollback planıyla üretime alırsınız?
  • Framework-dependent deployment'da runtime eksikse ve self-contained deployment'da güvenlik yaması unutulursa hangi hata ortaya çıkar?
  • C# 14 extension property, domain modeline gerçek anlam katıyor mu; yoksa extension method daha açık mı?
Uygulama vurgusuBir PR'da TFM, SDK pin'i, NuGet paket ana sürümleri, container base image, CI runner ve test matrisi ayrı ayrı gözden geçirilmelidir. “Build yeşil” fonksiyonel, performans ve güvenlik kabulü değildir.
